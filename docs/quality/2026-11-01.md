# Quality check, 2026-11-01

The ten engineering rules, checked against the code on `main`, with the evidence. Run on Windows 11
with Go 1.26.10 and Helm v4.3.0. The race detector needs cgo, which this machine does not have; CI
(Linux) runs `go test -race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | The seeder's HTTP client has a 10 s timeout, retries only connection errors and 5xx, at most 30 attempts 2 s apart, inside a 2-minute overall deadline (`internal/seeder/seeder.go`, `cmd/seeder/main.go`). The API server sets read, header, write and idle timeouts. Every helm and kind call carries `--wait`/`--timeout`, but `docker build`, `kind load` and `kubectl` had no limit, so a hung build would run until the 25-minute CI job was killed and teardown never ran. `etenv up` now gives all up steps a 15-minute deadline and `etenv down` 5 minutes (`cmd/etenv/main.go`); teardown keeps its own 5-minute budget after cancellation (`internal/envplan/run.go`, test `TestTeardownRunsWithALiveContextAfterCancellation`). `cmd/api` dropped the `srv.Shutdown` error; it is now logged. Remaining `_ =` are response writes to a client that has gone away and `flag.Parse` with `ExitOnError` (never returns an error). |
| 2 | Writes safe to retry | pass | The only server write is `PUT /api/dataset`, a full replace under one lock: a retried load gives the same data and the same checksum (new test `TestReloadIsIdempotent`, which fails when the load appends instead of replacing). A refused load leaves the previous data in place (`TestRefusesRawOrInvalidData` now loads a dataset first). `etenv` writes are deterministic overwrites of generated files (seed, stats, report); re-running produces identical bytes (`TestCommittedSeedMatchesRegeneration`). `kind create` on an existing name fails rather than reusing a cluster, and `etenv down` deletes it. |
| 3 | No race conditions | pass | The only shared state is the API's dataset: `replace` builds the new data and indexes outside the lock and swaps them under `mu.Lock`; reads copy under `RLock` (`internal/api/api.go`). `TestConcurrentReadsDuringReloads` runs 8 goroutines, under `-race` in CI. The envplan runner is sequential. |
| 4 | Don't trust the clock | pass | Step durations are `now().Sub(t)` with `now = time.Now` (`cmd/etenv/main.go`), which uses Go's monotonic reading. No timestamps are stored. Order dates are shifted calendar dates, not clock reads. |
| 5 | Read before changing | pass | One env var is read, `ETENV_ANON_KEY`, documented in the README "Run it" section and the Makefile. `HELM_*_HOME` and `KUBECONFIG` are set by the Makefile and the plan, not read. Every path in the README exists. |
| 6 | Never break compatibility | pass | The seed JSON shape, the API routes and the report JSON are unchanged. Strict decoding refuses unknown fields on purpose (raw data must never load); this is documented in RFC 0001. |
| 7 | One source of truth | pass | The chart's `files/seed.json` is generated from `testdata/raw.json` by `make seed`, and `TestCommittedSeedMatchesRegeneration` fails if it drifts. The API's `byID` and `orders` indexes are rebuilt on every `replace`. Go 1.26.10, Helm v4.3.0, kind v0.33.0 and the node image digest agree across README, `go.mod`, workflows, `scripts/get-tools.sh` and `envplan.DefaultNodeImage`. |
| 8 | Small changes, no secrets, validate input | pass | `git grep -iE "(api[_-]?key\|secret\|token\|password)\s*[:=]"`: only `automountServiceAccountToken: false`. The committed key is labelled `demo-key-only-for-the-synthetic-fixtures-in-this-repo`. Input validation: `Config.Validate` (PR, commit, digest, wait), `DecodeStrict` (4 MiB, unknown fields, trailing data), `Raw.Validate`, `Seed.Validate`, `NewClient` (scheme, host, no credentials), key length and k range. No new dependency. |
| 9 | Tests that can actually fail | fixed | No `t.Skip`, no assertion-free tests. Mutation check below: 4 of 14 mutants survived; each now has a test that kills it. |
| 10 | Re-verify | pass | `gofmt -l cmd internal`: empty; `go vet ./...`: clean; `helm lint --strict`: `1 chart(s) linted, 0 chart(s) failed`; `go test -count=1 ./...`: 41 passed, 7 packages `ok`; `etenv scan`: `scan clean: 247 customers, 597 orders, smallest group 5`; `etenv policy`: `6 objects ..., 3 containers, 0 violations`; `govulncheck@v1.8.0`: `No vulnerabilities found.`; `audit_repo.py`: `ephemeral-test-envs: OK`. CI on push. |

## Tests added (39 -> 41)

- `TestVerifyComparesTheCustomerReadBack`: an app whose counts and checksum match but whose
  customer read returns a changed display name is refused.
- `TestReloadIsIdempotent`: two identical PUTs give identical stats.
- New cases in existing tests: a full name embedded in other text, an amount over the limit, and
  a refused load after real data was loaded.

## Known limitations

None new. The race detector runs only in CI (no cgo on this machine).
